# 3.0 release checklist

Sequential — do these in order.

1. [ ] **Bump `package.json` version**: `packages/rspress/package.json` is
       currently `2.0.6`. Bump to `3.0.0`. No version-bump tooling/changeset
       exists in this repo, so this is a manual edit.
2. [ ] **Retitle CHANGELOG**: `[Unreleased]` in `CHANGELOG.md` is already
       substantial and well-formed — retitle it to `[3.0.0] - <date>` once
       everything above is done and no further changes are expected before
       publish.
3. [ ] **Full verification pass**: `pnpm check:all` (format + lint + build +
       typecheck + tests + knip + e2e) clean on the exact commit you intend to
       tag.
4. [ ] **Git tag**: existing tags are inconsistent (`v0.0.4`..`v1.0.0` prefixed
       with `v`, but `2.0.4-rc.2`/`2.0.6` bare). Continue using bare for
       `3.0.0` onwards.
5. [ ] **Publish / npm dist-tags**: `pnpm run release` covers most of this
       (no separate `RELEASING.md` needed). `latest` should move to `3.0.0`
       immediately, and the last `2.x` publish needs an explicit `@2` tag
       pointed at it.
6. [ ] **Version-tag guidance**: once 3.0 is out, `@2` becomes the legacy tag.
       Update `packages/rspress/README.md` and
       `website/docs/guide/getStarted.mdx` — both currently say "v2 = current,
       install `@1` for Rspress v1" — with the new row (root CLAUDE.md also
       notes this).
