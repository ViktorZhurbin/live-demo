# 3.0 release checklist

Sequential — do these in order.

1. [x] **Version-tag guidance**: `@2` is now the legacy tag for 3.0's
       breaking changes (independent of Rspress-core compat, which 3.0
       doesn't change — `peerDependencies` stays `@rspress/core >=2.0.0`).
       Added to `packages/rspress/README.md` and
       `website/docs/guide/getStarted.mdx` (root CLAUDE.md also noted this).
2. [x] **Retitle CHANGELOG**: `[Unreleased]` in `CHANGELOG.md` is already
       substantial and well-formed — retitle it to `[3.0.0] - <date>` once
       everything above is done and no further changes are expected before
       publish.
3. [ ] **Full verification pass**: `pnpm check:all` (format + lint + build +
       typecheck + tests + knip + e2e) clean on the exact commit you intend to
       tag.
4. [ ] **Version bump + tag**: `pnpm version major` from `packages/rspress/`
       (or `--filter @live-demo/rspress` from root) — bumps `package.json`,
       commits, and tags in one step (see `RELEASING.md`). Existing tags mix
       `v`-prefixed (`v0.0.4`..`v1.0.0`) and bare (`2.0.4-rc.2`/`2.0.6`); go
       with `pnpm version`'s default `v` prefix (`v3.0.0`) rather than
       fighting the tool — bare tags earlier were likely done manually, not a
       convention worth preserving.
5. [ ] **Push**: `git push --follow-tags` — pushes the version commit and the
       `v3.0.0` tag.
6. [ ] **Publish / npm dist-tags**: `pnpm run release` (root script: build +
       `pnpm --filter @live-demo/rspress publish`). `latest` moves to `3.0.0`
       automatically. Then point the legacy tag at the last `2.x` publish:
       `npm dist-tag add @live-demo/rspress@2.0.6 @2`.

## Rollback

If 3.0.0 turns out broken post-publish, point `latest` back at the last known
good version — no unpublish needed:

```sh
npm dist-tag add @live-demo/rspress@2.0.6 latest
```
